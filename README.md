## 分類、拆篇與檔名

- 城市資料夾依「中文 英文 韓文」順序命名，例如 `大邱 Daegu 대구`。
- 每個地點各自建立一個 `.md` 檔，放進對應城市資料夾；同一來源有多個城市或地點，也要分別整理。店家、市場、美食街各自成篇；僅作交通背景或延伸閱讀提及的地名不另建檔。
- 檔名使用「地點名稱－具體特色.md」，讓人直接辨識地點與特色。
- 新增前比對中、英、韓文名稱、分店與地址。同一景點或同一分店已有檔案，就閱讀舊文、比較新來源，把尚未收錄的特色融入原檔，不建立重複檔案；沒有新資訊才跳過。
- 更新舊文時保留原有有效內容與使用者提供的所有原始出處。不同店家、不同分店，不因名稱或料理相似而合併。
- 新增或調整文章連結時，同步維護城市索引。

## 寫作方式與特色細節

- 使用台灣用語與繁體中文，將重點寫成自然、生動、有畫面的新文章。可以借鏡原文的語氣、節奏與感官描寫，重新組織成有溫度的文字。
- 文章主體要介紹地點本身，不能只用一句空泛簡介，再堆上地址表格與查核說明。把食材、工序、風味、吃法、空間或歷史串起來，讓讀者理解這個地方值得留意的特色。
- 餐飲文章優先保留食材與部位、產地或供應來源、調味與藥草、器皿、前處理、烹調手法及搭配吃法；來源有說明其對風味或口感的作用時，一併寫入。不要把具體特色縮成「好吃」「有特色」。
- 景點與店舖文章保留建築、材料、格局、陳設、景觀、歷史及活動等辨識細節，不套用餐廳寫法。
- 名稱與食材保持合理正確，以能讓讀者理解料理為準，不吹毛求疵，不要求逐篇細分牛肉產地或品種；只有會影響料理理解或選擇的差別才自然說明。具體配方比例與製作時間不自行編造。
- 小標題依內容設計，段落有順序與節奏，不固定套用「到訪資訊／查核與安排提醒」。店家實用資訊放在正文後，來源放在文末。
- 不放圖片，不顯示整理日期或更新日期，不加入制式的實地到訪聲明。

## 地址、地圖與營業資訊

- 提供韓文店名、韓文地址與可點擊的地圖連結；視資料提供電話、營業時間、公休日及實用交通資訊。
- 優先查找 Naver 搜尋、Naver Place／Naver Map 店家資料，核對分店、地址、電話、入口與營業公告。保留實際找到的 Naver 店家連結，不猜測店家編號。
- Naver 資料不易取得時，主動查找可行的搜尋或讀取方式，使用韓文店名、電話搜尋，也可從韓文介紹與食記找到 Naver 店家連結；再以店方、地方官方及相關韓文文章交叉比對。
- Google 地圖保留作為輔助入口；只把韓文地址放進 Google 搜尋連結，不算完成定位查核。
- 官方已列明營業時間與公休日，直接呈現資訊即可，不附上舊文章的不同時段、工具讀取失敗或冗長的查核過程。
- 查核在整理過程完成，不讓研究過程占據正文，也不反覆使用「未確認」「出發前確認」等套話。只有歇業、分店辨識或地址衝突等確實影響前往且仍無法釐清的問題，才簡短註明。
- 未取得的資訊不假裝已查證，未確認的資料不補造。

## 延伸閱讀與原始文章出處

- 主動嘗試閱讀近兩年韓文 Naver 部落格，補充食材、手法、口感、吃法及現場細節；有價值的觀點直接融入全文，不必逐一列成延伸閱讀。找不到或讀不到時不冒稱已讀取，可交叉參考其他近期韓文介紹。
- 既有有幫助的延伸閱讀可以保留；新增搜尋的資料以融入文章為主，不必每篇都列一串連結。
- 文章最下方另設「原始文章出處」，保留使用者提供的原始文章連結，與自行搜尋的延伸閱讀分開。
- 同一來源拆成多篇，每篇都附原始出處；新來源補入舊文時，也將該來源加入原始出處清單。
- 原始出處不能只放在 README，也不能被延伸閱讀取代。
