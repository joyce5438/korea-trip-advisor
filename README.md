## 分類、拆篇與檔名

- 城市資料夾依「中文 英文 韓文」順序命名，例如 `大邱 Daegu 대구`。
- 每個地點各自建立一個 `.md` 檔，放進對應城市資料夾；同一來源有多個城市或地點，也要分別整理。店家、市場、美食街各自成篇；僅作交通背景或延伸閱讀提及的地名不另建檔。
- 檔名使用「地點名稱－具體特色.md」，讓人直接辨識地點與特色。
- 新增前比對中、英、韓文名稱、分店與地址。同一景點或同一分店已有檔案，就閱讀舊文、比較新來源，把尚未收錄的特色融入原檔，不建立重複檔案；沒有新資訊才跳過。
- 更新舊文時保留原有有效內容與使用者提供的所有原始出處。不同店家、不同分店，不因名稱或料理相似而合併。
- 新增或調整文章連結時，同步維護城市索引。
- 店家已歇業、暫停營業、搬遷後新址未能確認，或現況仍無法判定時，將文章放進該城市資料夾的 `待確認` 子目錄；索引也列在該城市的「待確認」小節。確認營業與正確位置後，再移回城市資料夾主目錄。

## 寫作方式與特色細節

- 使用台灣用語與繁體中文，將重點寫成自然、生動、有畫面的新文章。可以借鏡原文的語氣、節奏與感官描寫，重新組織成有溫度的文字。
- 文章主體要介紹地點本身，不能只用一句空泛簡介，再堆上地址表格與查核說明。把食材、工序、風味、吃法、空間或歷史串起來，讓讀者理解這個地方值得留意的特色。
- 餐飲文章優先保留食材與部位、產地或供應來源、調味與藥草、器皿、前處理、烹調手法及搭配吃法；來源有說明其對風味或口感的作用時，一併寫入。不要把具體特色縮成「好吃」「有特色」。
- 景點與店舖文章保留建築、材料、格局、陳設、景觀、歷史及活動等辨識細節，不套用餐廳寫法。
- 名稱與食材保持合理正確，以能讓讀者理解料理為準，不吹毛求疵，不要求逐篇細分牛肉產地或品種；只有會影響料理理解或選擇的差別才自然說明。具體配方比例與製作時間不自行編造。
- 正文提到韓文菜名、食材、部位、份量、點餐或文化用語時，先寫讀者看得懂的中文，再以括號保留韓文，即「中文（韓文）」。例如辣味烤腸（불곱창）、整盆（한바가지）、半盆（반바가지）；不要直接把韓文塞進中文句子，讓讀者自行猜意思。同一詞首次說明後，後文可只用中文。韓文店名與地址等實用資訊欄保留韓文原文。
- 翻譯依上下文理解；來源只足以確認「烤腸」時，不自行細化成某一腸段。沒有通行中文名稱的詞，以自然中文短語說明，再括註韓文，不以音譯代替意思。
- 小標題依內容設計，段落有順序與節奏，不固定套用「到訪資訊／查核與安排提醒」。店家實用資訊放在正文後，來源放在文末。
- 不放圖片，不顯示整理日期或更新日期，不加入制式的實地到訪聲明。

## 對比句與小標題

- 寫到「不是 A，而是 B」時，先檢查 A 是否為讀者確實可能相信、且需要澄清的說法。
- 若 A 是有效對比，保留 A 與 B 的關係，改用「不同於 A，B……」「比起 A，B……」「相較於 A，B……」等句法，避免反覆使用同一種轉折骨架。
- 若 A 只是寫作者自行設下的假想對立，不要把它換成另一種比較句；刪除 A，直接陳述 B。
- 小標題可以是完整句。只要它直接說出該段的具體內容，就不必為了縮短而改成意思模糊的名詞短語。
- 例如，「肉汁不是為了壓過紫蘇，而是替麵添一層圓潤」中的「壓過紫蘇」是無效的假想對立，應直接寫成「牛胸肉的肉汁讓紫蘇油蕎麥麵多了一層圓潤」；此句可作為小標題。

## 韓文全文如何融入文章

讀取全文與完成融入是兩個步驟。取得正文、列出來源連結或增加字數，都不代表文章已吸收新資料。

1. **先確認讀對地點與內容。** 比對店名、城市、分店及地址；閱讀正文，排除外地同名店、無關搜尋結果與廣告內容。搜尋摘要與讀取失敗不能記作已讀全文。
2. **整理可用的具體細節。** 將來源網址、適用店家、舊文缺少的資訊及預計融入段落，記在整理過程的工作筆記。餐飲優先找食材、前處理、醃漬、切法、火候、口感變化、蘸醬、配菜、點餐份量與收尾吃法；景點則找材料、格局、觀看角度、現場動線與歷史。工作筆記不放進旅遊正文。
3. **把細節寫成有關聯的敘事。** 寫出「怎麼做 → 帶來什麼口感或風味 → 怎麼搭配吃」，或「空間細節 → 從哪裡看 → 有什麼感受」。保留韓文食記裡的點餐思路、口味偏好與用餐節奏，重新組織成自然中文；不能把它們全部縮回「焦香、彈牙、有特色、適合聊天」等通用形容。
4. **守住細節的適用範圍。** 街區文章可用具名店家的吃法作例子，不能把一家店的初煮、醃醬、配菜或服務寫成整條街共同做法。食客偏好自然呈現為可選吃法；不同食記有差異時，先辨別分店、時期或個人感受。
5. **逐項對照成稿。** 回看工作筆記，確認有價值的新細節實際出現在正文，且解釋清楚與地點特色的關係。若刪去地名後，整段仍能套用到多數餐廳或景點，就回頭補入能辨識此處的內容。來源沒有新細節時不硬湊，也不宣稱已補充。
6. **分開確認研究與寫作成果。** 完成回報前，逐篇確認「取得了什麼」與「實際融入了什麼」。只讀過、尚未寫入的文章不能算完成融入；上傳成功或讀回一致只代表檔案寫入成功，還須完成內容對照。

### 安地朗烤腸街的改寫例子

- 不足的寫法：「烤腸外層焦香、裡頭有嚼勁，適合邊烤邊聊。」這類句子沒有呈現讀取韓文食記後增加的內容。
- 應保留的細節：以 Smile 烤腸的食記為例，整盆與半盆的點法、長條與圈切的偏好、先煮再醃醬的處理、醬料容易焦而需勤翻、青陽辣椒蘸醬、辣腸配起司，以及牛胸肉大醬湯配飯的收尾。
- 寫進正文時，沿著點菜、翻烤、搭配與收尾展開，讓細節帶動文章，而不是在泛泛的介紹後附上一串研究清單。上述做法須明確對應該店，不能概括成所有店家。
- 韓文食記可參考其觀察方式、情緒與節奏，轉化成有內容的中文敘事；不靠堆疊韓文字、驚嘆號或模仿口頭禪營造在地感。

## 地址、地圖與營業資訊

- 提供韓文店名、韓文地址與可點擊的地圖連結；視資料提供電話、營業時間、公休日及實用交通資訊。

- Naver 資料不易取得時，主動查找可行的搜尋或讀取方式，使用韓文店名、電話搜尋，也可從韓文介紹與食記找到 Naver 店家連結；再以店方、地方官方及相關韓文文章交叉比對。

- 官方已列明營業時間與公休日，直接呈現資訊即可，不附上舊文章的不同時段、工具讀取失敗或冗長的查核過程。
- 查核在整理過程完成，不讓研究過程占據正文，也不反覆使用「未確認」「出發前確認」等套話。只有歇業、分店辨識或地址衝突等確實影響前往且仍無法釐清的問題，才簡短註明。
- 未取得的資訊不假裝已查證，未確認的資料不補造。

## Naver 部落格全文讀取：實測方法

### 工具來源與用途

- 專案來源：[tjdwls101010／Agentic-Blog](https://github.com/tjdwls101010/Agentic-Blog)
- [原專案使用說明](https://github.com/tjdwls101010/Agentic-Blog/blob/main/README.md)
- 本次實測版本：`0.3.0`。工具以 Python 指令讀取公開 Naver 部落格，支援搜尋、日期篩選與文章正文讀取，不需 Naver 帳號或 API 金鑰。
- 用於查找近兩年的韓文食記，讀取全文後，將有價值的料理、口感、配菜與吃法細節自然融入既有文章。搜尋結果的摘要不等於已讀取全文。

### 安裝

需要 Python 3.11 以上版本。使用隔離環境安裝，避免影響其他工具：

```bash
git clone https://github.com/tjdwls101010/Agentic-Blog.git
cd Agentic-Blog
python -m venv .venv
source .venv/bin/activate
python -m pip install .
python -m agentic_blog --version
```

若執行環境使用 SOCKS 代理，另安裝其依賴；不需改變既有代理設定：

```bash
python -m pip install 'httpx[socks]'
```

### 延長請求等待時間至 25 秒

本次實測直接執行搜尋曾回傳 `ReadTimeout`；把 HTTP 請求逾時延長為 **25 秒** 後成功。以下包裝程式只延長等待時間，不修改原工具的請求間隔、數量限制或存取範圍。

在原專案目錄建立 `run_naver_blog.py`：

```python
import sys
import httpx
from agentic_blog.cli import main

_original_init = httpx.Client.__init__

def _init_with_longer_timeout(self, *args, **kwargs):
    kwargs.setdefault("timeout", 25.0)
    _original_init(self, *args, **kwargs)

httpx.Client.__init__ = _init_with_longer_timeout

if __name__ == "__main__":
    raise SystemExit(main(sys.argv[1:]))
```

這是本次驗證過的執行包裝方式，並非工具原生的 `--timeout` 參數。25 秒是 HTTP 等待設定，不是整個指令的總執行上限；外層執行環境也要允許足夠時間，指令仍在執行時應等待完成，不因數秒沒有輸出就判定失敗。

### 搜尋與讀取全文

先以韓文店名搜尋，日期隨當次執行日調整為近兩年，小量取得候選文章：

```bash
python run_naver_blog.py search '벙글벙글찜갈비' \
  --since 2024-10-26 --until 2026-10-26 \
  --limit 3 --output /tmp/naver-search.json
```

搜尋結果包含 `blog_id`、`log_no`、標題、日期與 `brief` 摘要。使用其中的部落格 ID 與文章編號讀取全文；不要把搜尋結果中只有部落格首頁的 `url` 當成文章網址：

```bash
python run_naver_blog.py post sun_38_ 224452612956 \
  --no-comments --output /tmp/naver-post.json
```

也可將完整文章網址傳給 `post`。本次未取留言，僅讀正文。

檢查結果是否真的包含正文：

```python
import json

with open("/tmp/naver-post.json", encoding="utf-8") as f:
    post = json.load(f)[0]

body = post.get("body") or ""
print(post.get("title"))
print("正文長度：", len(body))
print(body)
```
